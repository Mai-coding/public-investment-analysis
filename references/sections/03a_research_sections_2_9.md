## 第 2 章 行业纵向叙事（长度以 `scripts/depth_audit.py` 下限为准；4–6 页仅作规划）

**写作风格**：HV 纵向 narrative，prose 不是 bullets。行业术语只在首次出现时用一句短解释；**本章不得再放术语表/行业术语速览表**，统一术语表位于 §3 末尾。

### 必含子节 checklist
- [ ] 2.1 起源（IDEA 出处 + 时代环境）
- [ ] 2.2 诞生（具体人物 + 公司 + 年份）
- [ ] 2.3 死亡之谷 / 早期挑战
- [ ] 2.4 拐点（明确触发事件）
- [ ] 2.5 第二曲线 / 产业链重组
- [ ] 2.6 当前阶段
- [ ] 2.7 时间线表格（10+ 关键节点，每节点带年份）
- [ ] **2.8 价值链全景**（取代旧版 2.9，详见 `recipes/18c_value_chain.md`）

### 2.8 价值链全景硬性规格

1. 4 列环节表：「环节」｜「做什么」｜「主要玩家」｜「商业模式与议价权」，覆盖 5–8 个环节并标 target 主场。
2. 价值分布图：优先使用目标公司同口径分部收入、EBITDA、Capex；只有披露不足时才用跨公司毛利率代理并显式标 `Inference`。
3. “谁赚走了钱”分析：解释稀缺性、标准化、议价权和 target 迁移路线；每个迁移结论至少挂一个同公司分部指标。
4. 上中下游都写“对 target 的意义”，不做无结论名单。

**关联图表**：行业时间线、产业链/价值分布图。所有时间线必须通过最终尺寸文字重叠检测；年份拥挤时使用多车道或拆图。

## 第 3 章 核心技术入门（写给非技术读者；3–5 页）

**定位**：建立读完全报告所需的最小技术与财务背景。**不得包含 guidance、季度指引历史或管理层可信度分析**；这些内容统一放在 §9。

### 必含子节 checklist
- [ ] 开篇说明读者假设与阅读目的
- [ ] 3.0 背景知识清单：3–5 条最小知识集
- [ ] 3.1–3.x 主体 3–5 小节，按公司业务技术堆栈组织
- [ ] “与你日常印象的对照”小节
- [ ] **唯一术语表（Glossary）**：放本章末尾，合并全报告技术及必要财务术语，15–25 条；不得在 §2 重复

### 写作纪律
- 每个概念用“类比 + 解决的问题 + 与公司商业位置连接”；类比不能代替机制。
- 第一次出现缩写时正文就地写全称/短解释，后续由 §3 术语表统一检索。
- 术语去重：同义词合并为一个主条目，别名放括号；不要因为 §2 已解释过就再造第二张表。
- 本章只讲技术理解，不承担 management guidance 或估值历史。

## 第 4 章 产品分析（3–5 页）

**默认读者完全不懂行业。** 每个核心产品首次出现须给：一句话定义、工作原理、客户价值/商业类比。

### 必含子节 checklist
- [ ] 4.1 产品矩阵概览：产品 / 一句话定义 / 计价单位或收入模式 / 客户 / 当前阶段
- [ ] 4.2 主力产品：参数、定价逻辑、客户及竞争替代路径
- [ ] 4.3 第二曲线 / 新业务：2–3 条增长曲线与商业化时间表
- [ ] 4.4 高利润细分及组合迁移：量化收入/毛利贡献和验证指标
- [ ] 4.5 用户视角：必须品程度、替换原因、好坏标准，以陈述段落呈现
- [ ] **2–3 张真实产品/资产图片**：不是数据图；必须遵守 `17_product_images.md`，DOCX alt text 以 `PRODUCT_IMAGE:` 开头

### 产品图片硬门槛

- 2–3 张图片覆盖核心利润池、主力产品和至少一条第二曲线；半导体标的可使用官方芯片封装、开发板、产品家族或产品架构图。
- 图片放在对应子节正文之后，配图说明只放数字上标引用，不放完整来源或 URL。
- §4 的普通数据图、路线图和矩阵不能替代产品图。
- Task 1 先形成候选图片清单并保存来源；Task 5 必须实际插入。`report_content_audit.py` 会按 `PRODUCT_IMAGE:` alt text 计数，少于 2 张即 FAIL。

## 第 5 章 技术分析（**推导式**，3-5 页）

> ⚠️ v3 起本章替换为**推导式技术分析**写法（替换原"参数对比表"式写法），完整配方见 `recipes/18a–18f` 配方四。
> **原则**：每个结论都必须从第一性原理出发一步步推导，读者可以在任何一步提出异议。禁止直接照搬材料里的结论性表述（"利用率 70-80%" 必须推导出"为什么会差这么多倍"）。

### 必含子节 checklist
- [ ] 5.1 核心技术壁垒——**逐条壁垒一小节，标题用「推导 N：为什么 X」句式**，内文五步：①物理/数学/经济约束 → ②业务门槛（用户感知阈值/客户决策标准）→ ③推出"唯一解/必然选择" → ④可验证证据（财报数字对照，如毛利率差 = 架构差异的财务表达）→ ⑤明示推导的脆弱前提（直通风险章与反向 DCF 的分歧变量）
- [ ] 5.2 成本对比（含 chart 6；成本差也要推导出"为什么"，不只列数）
- [ ] 5.3 关键技术演进（代际路线图表）
- [ ] 5.4 垂直一体化 / 制造体系（如适用）
- [ ] 5.5 监管 + 牌照资产（如适用）
- [ ] 5.6 技术风险评估表——**同样推导式**：每层壁垒配一个"破口推导"（什么条件下失效）+ 烈度 + 早期信号，形成「壁垒→破口」一一对应表

### 与其他章的咬合 ⚠️ 强制
技术壁垒结论必须显式回链到 ①第 15 章评分的竞争力分数 ②第 11 章 priced-in 对照里"市场与我们分歧的技术根源"。技术分析不是孤岛，它是估值分歧的底层证据链。

**自检**：把每个"推导 N"小节的第一步遮住，问：结论还成立吗？若成立，说明推导是装饰性的，重写。

## 第 6 章 市场分析（3-5 页）

### 必含子节 checklist
- [ ] 6.1 TAM/SAM/SOM 三层拆解（**必须用同一个 source 口径**；第三方**预测**数据优先用发布日期 **≥ 2025-01-01** 的 vintage，并标报告发布日期，旧 vintage 仅在无更新版本时用且标 stale）
- [ ] 6.2 增长驱动（按短/中/长期分类，每段 4-5 项）
- [ ] 6.3 行业挑战（按因素分类，按重要性排序，糅合陈述句）

### 6.3 行业挑战写法 ⚠️

按重要性排序的因素列表：技术 / 商业化 / 监管 / 资本 / 地缘 / 客户认知。每项必须包含：
- 现状描述（陈述句，非问句）
- 时间线
- 影响烈度（归零级 / 重大 / 次级）
- 早期信号

## 第 8 章 商业模式、收入引擎与股东经济学（长度以审计下限为准；4–6 页仅作规划）

本章回答“公司如何把产品变成收入、利润和每股价值”，不能只列收入占比和几个利润率。

### 必含子节 checklist
- [ ] **8.1 收入结构与迁移路径**：3–5 年历史 + 3–5 年预测（若模型可得），按公司披露最有解释力的 segment/product/end-market/region 拆分
- [ ] **收入结构图（强制）**：历史与预测堆叠柱，显示金额、占比和总额；DOCX alt text 以 `CHART_REVENUE_MIX:` 开头
- [ ] 8.2 收入引擎与合同经济：计价单位、设计赢单/订单到收入的周期、NRE/订阅/交易/项目收入及可见度
- [ ] 8.3 单位经济与客户绑定：选择适用单位，解释获客、attach、续代、留存/切换成本；不机械套 SaaS LTV/CAC
- [ ] 8.4 客户集中、议价权和收入尾部：前五/前十大、单客户/单项目风险及替代路径
- [ ] 8.5 生产模式、供应链和营运资本：上游依赖、产能承诺、库存/预付款/现金转换
- [ ] 8.6 利润池与经营杠杆：毛利、R&D、销售费用、人效、FCF 与 3–5 家可比公司的同口径表
- [ ] 8.7 资本配置、SBC、摊薄与每股价值：回购/并购/分红及完全摊薄 FCF 结果
- [ ] 8.8 商业壁垒和失效条件：1–2 个核心壁垒，各自配可证伪 KPI

### 深度硬要求

- 至少 2 张分析表 + 1 张收入结构图。
- 不能用“公司未披露 ARPU”结束单位经济分析；要改用行业适用的最小经济单元并说明限制。
- 所有结构变化必须解释驱动：量、价、mix、客户/产品迁移和会计口径。
- 章节结论落到每股价值，而不止公司层面收入增长。

## 第 9 章 管理层、治理与执行可信度（长度以审计下限为准；4–6 页仅作规划）

管理层档案卡只是导航，**不能替代逐人分析**。本章要回答：谁对关键假设负责、过去做成过什么、风格是什么、哪一项仍未验证。

### 必含子节 checklist
- [ ] 9.1 创始文化与治理历史：技术基因、资本纪律和历史教训
- [ ] 9.2 CEO 阶段匹配与资本配置：任期、关键决策、量化结果、失败/争议
- [ ] **9.3 管理层深度画像**：5–7 位关键人物，每人使用独立三级标题 `9.3.1 姓名｜职务`、`9.3.2 ...`
- [ ] 9.4 组织结构、职责边界与跨团队协同
- [ ] 9.5 董事会、激励、SBC、内部人持股/交易与股东一致性
- [ ] 9.6 继任、关键人、并购团队留任与组织风险
- [ ] **9.7 Guidance 演变与可信度**：最近 5 次电话会的指引、实际、偏差、解释、短期/长期 guidance 区分
- [ ] 9.8 阶段结论：团队能否完成未来 2–3 年的关键任务
- [ ] 管理层档案卡图：5–6 人摘要卡，遵守 `recipes/18f_management_profiles.md`

### 每位管理层画像的最低内容

每个 `9.3.x` 块至少包含：

1. 背景、加入时间和当前职责；
2. 2–3 个与本公司关键任务直接相关的量化 track record；
3. 决策/运营/资本配置风格及证据；
4. 对未来 thesis 的具体责任；
5. 一个风险、争议或尚未验证项。

单纯列姓名、职位和两行职责不合格。至少 5 个 profile，每个建议 180–300 中文字符；机器闸门会检查 profile 数量、数字和风险信号。

### Guidance 分析纪律

- 单季/年度指引兑现与 2–3 年长期目标分开评分；不能因为连续 beat 单季中点就自动认定长期目标可信。
- 解释误差来自保守引导、需求变化、并表、供给或执行中的哪一项。
- 把 guidance 可信度连接到预测置信区间和估值，而不是孤立放一张表。
- 过去 12 个月股价归因不放在本章；它作为 Task 1 后台诊断交给 Task 3，最终放 §11.0。

## v2 consolidated minimum outputs and pre-answered questions

## §2 行业纵向叙事 —— 追加
**最低产出物**：时间线表（10+ 节点）；§2.8 价值链全景（环节表 + 价值分布图 + “谁赚走了钱”段）。本章不设术语表，术语只在首次出现时简释并统一收录 §3。
**预答追问**：①这个行业的"死亡之谷"是什么、谁死了？②当前拐点的触发事件 + 具体日期？③钱在链条上怎么分、target 正向哪个环节迁移？

## §3 核心技术入门（科普章）—— 追加
**最低产出物**：背景知识清单；主体 3–5 小节；日常类比；全报告唯一术语表（15–25 条）。本章不得放 guidance。
**预答追问**：①一个高中知识水平的读者读完本章，能否不回查任何资料读懂全报告？②正文是否还有未入术语表的缩写/行话（grep 全大写缩写核查）？

## §4 产品分析 —— 追加
**最低产出物**：产品矩阵；主力产品“参数·定价·客户”分析；组合迁移；**2–3 张实际插入 DOCX 的产品/资产图片**，使用 `PRODUCT_IMAGE:` alt text 和数字上标引用。
**预答追问（2 个，深答）**：①为什么客户非用这个产品/这种电源不可、替代品差在哪？（"为什么非核电不可"式，必须配电源/产品对照表）②客户原来用什么、为什么放弃旧方案转过来？（切换的驱动 + 转换成本）

## §5 技术与资产分析 —— 追加
**最低产出物**：①任何"牌照/资质/专利"类壁垒，必须配**"数量 + 门槛分层"表**（有多少张/多少容量、谁持有、门槛分哪几层）；②**全行业供给全景表**（全国/全球总量 + 各玩家持有 + 标的份额 + 可寻址真实分母）；③颠覆性新技术的**"替代 vs 互补"分析**（成本 $/单位·LCOE + 商运时间线 + 标的应对 5 条）。
**预答追问**：①壁垒具体几张牌照、门槛在哪？②标的占全行业多少（名义口径 + 可寻址口径两个数）？③新技术（如 SMR）2030 后会否替代存量资产、标的如何应对？

## §6 市场分析 —— 追加
**最低产出物**：**美元口径 TAM/SAM/SOM 表**（美元/年，不能只给物理量）；标的**份额 + 份额轨迹**；增量市场（如数据中心）的美元规模 + 配套资本开支。
**预答追问**：①市场到底多少美金？②标的现在占百分之几、未来到多少？③增量份额 vs 存量份额分别多少（区分"存量盘"与"增量盘"）？

## §7 竞争横向叙事 —— 追加
**最低产出物**：每家竞品 5 段 narrative；CR3/CR5（带来源）；**下游大客户全景表**（谁向谁下单、规模、金额、投运时间）；**对手方"威胁性 × 时间维度"表**（近期 ≤N 年 / 远期威胁分级）。
**预答追问**：①对手能拿到大单，是否说明市场不集中？（必须按"现役可交付 vs 在建/概念期权"拆两个时间维度回答）②谁是近期同质竞争、谁只是远期期权？③集中度的"正确分母"是什么？

## §8 商业模式 —— 追加
**最低产出物**：单位经济学/利润率对比表（含同业）；护城河展开（1–2 条，每条给"机制 + 反方"）。
