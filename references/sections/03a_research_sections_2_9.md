# Section Specifications — Task Slice

> This is the authoritative task-specific slice of the public 16-section specification; no legacy monolith is required.
> Mechanical floors and required markers are owned by `scripts/depth_audit.py`; page and word ranges below are planning guidance only. Images/charts appear after the supporting subsection prose, never at the subsection opening.

## 第 2 章 核心技术入门（写给非技术读者；3–5 页）

**定位**：建立读完全报告所需的最小技术与财务背景。**不得包含 guidance、季度指引历史或管理层可信度分析**；这些内容统一放在 §9。

### 必含子节 checklist
- [ ] 开篇说明读者假设与阅读目的
- [ ] 2.0 背景知识清单：3–5 条最小知识集
- [ ] 2.1–2.x 主体 3–5 小节，按公司业务技术堆栈组织
- [ ] “与你日常印象的对照”小节
- [ ] **唯一术语表（Glossary）**：放本章末尾，合并全报告技术及必要财务术语，15–25 条；不得在 §3 重复

介绍性段落、知识依赖及段落衔接遵循 `21_report_editorial_style.md`；复杂技术按需读取 `recipes/18a_core_technology_explainer.md`。不承担管理层指引或估值历史。

## 第 3 章 行业纵向叙事（长度以 `scripts/depth_audit.py` 下限为准；4–6 页仅作规划）

**写作风格**：HV 纵向 narrative，prose 不是 bullets。行业术语只在首次出现时用一句短解释；**本章不得再放术语表/行业术语速览表**，统一术语表位于 §2 末尾。

历史介绍按时代背景、关键选择及后果自然推进，先保证可读性；不要求每段都加数字、风险和估值含义。进入价值链利益分配等分析时，再使用结论与证据的写法，见 `21_report_editorial_style.md`。

### 必含子节 checklist
- [ ] 3.1 起源（IDEA 出处 + 时代环境）
- [ ] 3.2 诞生（具体人物 + 公司 + 年份）
- [ ] 3.3 死亡之谷 / 早期挑战
- [ ] 3.4 拐点（明确触发事件）
- [ ] 3.5 第二曲线 / 产业链重组
- [ ] 3.6 当前阶段
- [ ] 3.7 时间线表格（10+ 关键节点，每节点带年份）
- [ ] **3.8 价值链全景**（详见 `recipes/18c_value_chain.md`）

### 3.8 价值链全景硬性规格

1. 4 列环节表：「环节」｜「做什么」｜「主要玩家」｜「商业模式与议价权」，覆盖 5–8 个环节并标 target 主场。
2. 价值分布图：优先使用目标公司同口径分部收入、EBITDA、Capex；只有披露不足时才用跨公司毛利率代理并显式标 `Inference`。
3. “谁赚走了钱”分析：解释稀缺性、标准化、议价权和 target 迁移路线；每个迁移结论至少挂一个同公司分部指标。
4. 上中下游都写“对 target 的意义”，不做无结论名单。

**关联图表**：行业时间线、产业链/价值分布图。所有时间线必须通过最终尺寸文字重叠检测；年份拥挤时使用多车道或拆图。

## 第 4 章 产品分析（3–5 页）

**默认读者完全不懂行业。** 每个核心产品首次出现须给：一句话定义、工作原理、客户价值/商业类比。

### 必含子节 checklist
- [ ] 4.1 收费产品矩阵：已商业化产品/服务、定义与计价、客户、最新完整年度收入及年份。未单独披露则注明，不强拆；并购等重大变化另列最新期间，不能与全年相加。技术路线、合同形式和未产收的建设/研发项目不重复列为产品，后者放增长储备。
- [ ] 4.2 客户价值：紧接矩阵，解释谁购买、解决什么问题、原有方案、切换原因与好坏标准；比较替代方案成立的条件，不预设产品不可替代。
- [ ] 4.3 主力产品：参数、定价逻辑、客户及竞争替代路径
- [ ] 4.4 第二曲线 / 新业务：增长储备、商业化时间与尚待兑现条件
- [ ] 4.5 高利润细分及组合迁移：量化收入/毛利贡献和验证指标
- [ ] **2–3 张真实产品/资产图片**：不是数据图；必须遵守 `17_product_images.md`，DOCX alt text 以 `PRODUCT_IMAGE:` 开头

### 产品图片硬门槛

- 2–3 张图片覆盖核心利润池、主力产品和至少一条第二曲线；半导体标的可使用官方芯片封装、开发板、产品家族或产品架构图。
- 图片放在对应子节正文之后，配图说明只放数字上标引用，不放完整来源或 URL。
- §4 的普通数据图、路线图和矩阵不能替代产品图。
- Task 1 先形成候选图片清单并保存来源；Task 5 必须实际插入。`report_content_audit.py` 会按 `PRODUCT_IMAGE:` alt text 计数，少于 2 张即 FAIL。

## 第 5 章 技术分析（**推导式**，3-5 页）

### 必含子节 checklist
- [ ] 5.1 核心技术壁垒：按 `recipes/18d_derived_technical_analysis.md` 推导优势的成立条件、证据与失效边界。
- [ ] 5.2 成本对比：给有来源的参照并解释高低及商业影响；区分资本回收、边际运行与全成本，不由局部成本推断项目总回报。
- [ ] 5.3 技术演进：成本、商运时间、替代/互补关系与标的应对，区分现役可交付供给与远期选择。
- [ ] 5.4 垂直一体化 / 制造体系（如适用）
- [ ] 5.5 监管/牌照（如适用）：数量与门槛分层表；供给全景列总量、各玩家、标的份额及真实可寻址分母。
- [ ] 5.6 技术风险评估表——**同样推导式**：每层壁垒配一个"破口推导"（什么条件下失效）+ 烈度 + 早期信号，形成「壁垒→破口」一一对应表

### 与其他章的咬合 ⚠️ 强制
技术壁垒结论必须显式回链到 ①第 15 章评分的竞争力分数 ②第 11 章 priced-in 对照里"市场与我们分歧的技术根源"。技术分析不是孤岛，它是估值分歧的底层证据链。

**自检**：证据与约束能否支持判断，替代条件是否可证伪；标题句式和转折词不能代替推理。

## 第 6 章 市场分析（3-5 页）

### 必含子节 checklist
- [ ] 6.1 TAM/SAM/SOM 金额表（美元/年）、标的份额与轨迹、增量市场及配套资本；三层拆解（**必须用同一个 source 口径**；第三方**预测**数据优先用发布日期 **≥ 2025-01-01** 的 vintage，并标报告发布日期，旧 vintage 仅在无更新版本时用且标 stale）
- [ ] 6.2 增长驱动（按短/中/长期分类，每段 4-5 项）
- [ ] 6.3 行业挑战（按因素分类，按重要性排序，糅合陈述句）
- [ ] **市场分析总览图**（强制出图，见 `recipes/18a–18f` 配方五）：单图双面板——左 = TAM/SAM/SOM 三层漏斗（每层标金额+年份+占比；详细定义与来源按 `21_report_editorial_style.md` 及 `20_citation_and_source_appendix.md` 分流，SOM 层文字放条外避免挤压），右 = 增长驱动按"短期 0-12月 / 中期 1-3年 / 长期 3-5年+"三色带各列 3 条驱动；副标题放"未计入的增量 TAM"（期权部分）

### 6.3 行业挑战写法 ⚠️

按重要性排序的因素列表：技术 / 商业化 / 监管 / 资本 / 地缘 / 客户认知。每项必须包含：
- 现状描述（陈述句，非问句）
- 时间线
- 影响烈度（归零级 / 重大 / 次级）
- 早期信号

## 第 7 章 竞争横向叙事（长度以 `scripts/depth_audit.py` 下限为准；5-8 页仅作规划）

### 必含子节 checklist
- [ ] 7.1 竞争判断与评分解读（**纯文字分析**；chart 4 是本节唯一评分矩阵）
- [ ] 7.2 可比公司逐家展开（**4-5 家**，每家 5 段 narrative）
- [ ] 7.3 同赛道二线 / 补充玩家
- [ ] **7.4 市场集中度分析**（必须包含 CR3/CR5 + 可追溯来源（工作底稿完整记录；最终数字上标））⚠️
- [ ] 7.5 竞争定位四象限、大客户全景（买卖双方、规模/金额、投运时间）及近期/远期威胁表；chart 17 两轴及逐家定位证据按 `04_chart_inventory.md`，不能用评分矩阵替代
- [ ] 7.6 趋势判断（4-5 个 bullets）

### 7.1 去重写作规则

- 不得在正文中再放一张与 chart 4 重复的评分矩阵表，也不得把图中所有分数按行重述。
- 用 3–5 段解释：评分维度为何能区分胜负、标的的相对强项/短板、哪些对手近期最危险、综合分被哪些 trade-off 拉低，以及什么证据会改变判断。
- 图放在支撑文字之后，DOCX alt text 以 `CHART_COMPETITION:` 开头。分数的完整来源和口径留在 chart manifest/工作底稿。

### 7.2 每家竞品必须 5 段 narrative profile（**总 1000-1400 字**）

1. **怎么走到今天的**（300-400 字）
   - 创始年份 / 创始人 / 关键决策 / 重大事件
2. **独特赌注**（160-240 字）
   - 1-2 个核心策略选择
3. **用户/业内 perception**（160-320 字）
   - 必须有具体用户反馈（不能用"市场反响良好"等空话）
4. **真正的瓶颈**（160-240 字）
   - 具体的内部 / 外部约束
5. **vs Target 判断 + 威胁等级**（100-160 字）
   - 明确威胁等级（高/中-高/中/低）

### 7.4 市场集中度 ⚠️
- 必须给出 CR3 + CR5 具体数字
- 工作底稿必须记录准确数据来源与推算链；最终报告仅放数字上标
- 必须给出未来集中度趋势判断

## 第 8 章 商业模式、收入引擎与股东经济学（长度以审计下限为准；4–6 页仅作规划）

本章回答“公司如何把产品变成收入、利润和每股价值”，不能只列收入占比和几个利润率。

### 必含子节 checklist
- [ ] **8.1 收入结构与迁移路径**：3–5 年历史 + 3–5 年预测（若模型可得），按公司披露最有解释力的 segment/product/end-market/region 拆分
- [ ] **收入结构图（强制）**：历史与预测堆叠柱，显示金额、占比和总额；DOCX alt text 以 `CHART_REVENUE_MIX:` 开头
- [ ] 8.2 收入引擎与合同经济：先解释重大且不直观的收入/成本包含什么、为何发生、变化驱动与承担方，再分析计价、订单到收入及净利润。商业机制留正文，会计对账入方法附录。
- [ ] 8.3 单位经济与客户绑定：选择适用单位，解释获客、attach、续代、留存/切换成本；不机械套 SaaS LTV/CAC
- [ ] 8.4 客户集中、议价权和收入尾部：前五/前十大、单客户/单项目风险及替代路径
- [ ] 8.5 生产模式、供应链和营运资本：上游依赖、产能承诺、库存/预付款/现金转换
- [ ] 8.6 利润池与经营杠杆：毛利、R&D、销售费用、人效、FCF 与 3–5 家可比公司的同口径表
- [ ] 8.7 资本配置、SBC、摊薄与每股价值：回购/并购/分红及完全摊薄 FCF 结果
- [ ] 8.8 商业壁垒和失效条件：1–2 个核心壁垒，各自配可证伪 KPI

### 深度硬要求

- 至少 2 张分析表 + 1 张收入结构图。
- 不能用“公司未披露 ARPU”结束单位经济分析；要改用行业适用的最小经济单元并说明限制。
- 所有结构变化必须解释驱动：量、价、mix、客户/产品迁移和会计口径。
- 章节结论落到每股价值，而不止公司层面收入增长。

## 第 9 章 管理层、治理与执行可信度（长度以审计下限为准；4–6 页仅作规划）

管理层身份、履历与职责须由官网或 filing 核实；档案卡只是导航，**不能替代逐人分析**。本章要回答：谁对关键假设负责、过去做成过什么、风格是什么、哪一项仍未验证。

### 必含子节 checklist
- [ ] 9.1 创始文化与治理历史：技术基因、资本纪律和历史教训
- [ ] 9.2 CEO 阶段匹配与资本配置：任期、关键决策、量化结果、失败/争议
- [ ] **9.3 管理层深度画像**：5–7 位关键人物，每人使用独立三级标题 `9.3.1 姓名｜职务`、`9.3.2 ...`
- [ ] 9.4 组织结构、职责边界与跨团队协同
- [ ] 9.5 董事会、激励、SBC、内部人持股/交易与股东一致性
- [ ] 9.6 继任、关键人、并购团队留任与组织风险
- [ ] **9.7 Guidance 演变与可信度**：最近 5 次电话会的指引、实际、偏差、解释、短期/长期 guidance 区分
- [ ] 9.8 阶段结论：团队能否完成未来 2–3 年的关键任务
- [ ] 管理层档案卡图：5–6 人摘要卡，遵守 `recipes/18f_management_profiles.md`

### 每位管理层画像的最低内容

每个 `9.3.x` 块至少包含：

1. 背景、加入时间和当前职责；
2. 2–3 个与本公司关键任务直接相关的量化 track record；
3. 决策/运营/资本配置风格及证据；
4. 对未来 thesis 的具体责任；
5. 一个风险、争议或尚未验证项。

单纯列姓名、职位和两行职责不合格。至少 5 个 profile，每个建议 180–300 中文字符；机器闸门会检查 profile 数量、数字和风险信号。

### Guidance 分析纪律

- 单季/年度指引兑现与 2–3 年长期目标分开评分；不能因为连续 beat 单季中点就自动认定长期目标可信。
- 解释误差来自保守引导、需求变化、并表、供给或执行中的哪一项。
- 把 guidance 可信度连接到预测置信区间和估值，而不是孤立放一张表。
- 过去12个月股价归因放 §11.0；逐篇外部素材/预测的比较及独立核对放 Methods，正文保留影响判断的分歧与不确定性。
