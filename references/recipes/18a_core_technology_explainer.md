# Recipe 18a — Core Technology Explainer (§3)

> Load this self-contained recipe only when writing the named section; no legacy collection is required.

## 配方一：§3 核心技术入门（写给非技术读者）

**定位**：放在 §2 行业叙事之后、产品分析之前。读者读完它，后面 13 章不再需要任何技术背景。

**硬性规格**：
1. 开篇一句斜体说明："本章假设读者只具备高中知识水平…已熟悉者可跳到 §3.x 术语表"。
2. **§3.0 背景知识清单**（强制）：列出"读懂全报告所需的最小知识集"，通常 3-5 条，
   每条一句话。技术类（互联网如何工作/什么是云）+ 财务类（为什么用 P/S 而非 P/E）都要覆盖。
3. 主体 3-5 小节，按「公司业务的技术堆栈」组织（如 NET 案例：网页访问之旅→安全→
   开发者平台→AI/agent），**不按教科书目录组织**。
4. 每个概念三件套：**类比**（生活场景）+ **它解决什么问题** + **与公司商业位置的连接**。
   - 类比要全章一贯（NET 案例用"点外卖/连锁店/前台"贯穿始终，不要每段换一个比喻体系）。
   - 不允许只给类比不给机制——类比负责"懂"，机制负责"准"。例：
     "CDN=连锁分店"之后必须落到"内容提前备在离你近的节点，所以快"。
5. **「与你日常印象的对照」小节（强制）**：把技术锚定到读者亲身见过的场景
   （NET 案例：人机验证页面、Error 522、那次全网宕机新闻、ChatGPT 引用新闻网站）。
   这是科普章记忆度最高的一节，也是"和读者对该技术的印象建立联系"的直接实现。
6. 配图：优先用 filing 图片（网络覆盖图/产品 UI），让读者"看见"抽象概念。
7. 长度：3-5 页（含术语表）。语言禁令：不出现未在本章定义过的缩写；
   每段 ≤5 行；不堆参数。

**写作自检**：随机抽一段给"没有技术背景的聪明人"画像测试——若需要回查其他章节才能懂，重写。
