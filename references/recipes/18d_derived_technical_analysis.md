# Recipe 18d — Derived Technical Analysis (§5)

> Load this self-contained recipe only when writing the named section; no legacy collection is required.

## 配方四：推导式技术分析（替换"参数对比表"式写法）

**原则**：技术分析章的每个结论都必须**从第一性原理出发一步步推导**，读者可以在任何
一步提出异议。禁止直接照搬材料里的结论性表述（"利用率 70-80%"必须推导出
"为什么会差这么多倍"）。

**结构模板**：每条壁垒一小节，标题用「推导 N：为什么 X」句式，内文五步：
1. **第一步给物理/数学/经济约束**（光速极限、N×M vs N+M 成本结构、利用率×资本占用）；
2. **第二步给业务门槛**（用户感知阈值/客户决策标准）；
3. **第三步推出"唯一解/必然选择"**；
4. **第四步给可验证证据**（财报数字对照：如毛利率差 16pt = 架构差异的财务表达）；
5. **第五步明示推导的脆弱前提**（"此推导依赖边缘推理占比这一未决变量"）——
   这一步直通风险章与反向 DCF 的分歧变量。

**风险小节同样推导式**：每层壁垒配一个"破口推导"（什么条件下失效）+ 烈度 + 早期信号，
形成「壁垒→破口」一一对应表。

**与其他章的咬合**：技术壁垒结论必须显式回链到 ①评分章的竞争力分数 ②估值章
priced-in 对照里"市场与我们分歧的技术根源"。技术分析不是孤岛，它是估值分歧的
底层证据链。

**自检**：把每个"推导 N"小节的第一步遮住，问：结论还成立吗？若成立，说明推导
是装饰性的，重写。
