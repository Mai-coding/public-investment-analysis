# 12 - 运行时兼容与长任务执行

本文件是 `public-investment-analysis` 的运行时适配层。方法论文件只描述需要完成的能力；具体工具按当前环境映射。目标是同时兼容 Claude Code / Claude Cowork 与 ChatGPT / Codex，并在其他 agent 运行时中可降级执行。

---

## 一、总原则：按能力选择，不假定工具名

开始每个 task 前先确认：

1. 当前运行时和权限边界；
2. 操作系统与 shell；
3. 可用的用户输入、计划、网页、文件、图片、表格和文档能力；
4. 联网、工作区外写入、删除及长任务是否需要审批；
5. 缺少某项能力时的 fallback。

不要因为参考文件出现某个平台的工具名，就假定该工具在当前会话存在。不要通过绕过沙盒、私自扩权或让用户重复执行本可由当前运行时完成的步骤来解决能力差异。

---

## 二、Claude 与 ChatGPT/Codex 能力映射

| 需要的能力 | Claude Code / Cowork 常见实现 | ChatGPT / Codex 常见实现 | 平台无关指令 |
|---|---|---|---|
| 向用户确认输入 | `AskUserQuestion` 或直接提问 | 结构化用户输入工具（若可用）或直接提问 | “向用户确认”；不要硬编码工具名 |
| 跟踪多步工作 | `TaskList` / `TaskUpdate` | `update_plan` 或当前计划工具 | 建立可检查的执行计划并及时更新 |
| 读取文本文件 | `Read` | 文件读取或 shell 只读命令 | 读取所需文件，长文件分段直至 EOF |
| 编辑文本文件 | `Write` / `Edit` | `apply_patch` 或当前结构化编辑工具 | 使用当前运行时认可的文件编辑方式 |
| 查看本地图片 | `Read` 图片 | `view_image` 或当前图片查看能力 | 对每张图片做视觉 QA |
| 搜索与打开网页 | `WebSearch` / `WebFetch` / browser skill | web 搜索、浏览器或 Playwright 能力 | 使用当前可用网页工具并保留 URL/日期 |
| 运行命令 | Bash | 当前 shell；Windows 常为 PowerShell | 先识别 shell，再生成对应命令 |
| 表格构建 | `xlsx` skill 或库 | 表格 skill（若有）或 `openpyxl` 等 | 优先专用能力；否则用已安装 XLSX 库 |
| DOCX 构建 | `docx` skill 或库 | 文档 skill（若有）或 `python-docx`/`docx-js` | 优先专用能力；否则用已安装 DOCX 库 |
| 连接外部数据 | MCP / connector | MCP / app / plugin / connector | 仅使用当前已连接来源；失败按数据 fallback 处理 |
| 长任务等待 | 运行时等待、后台或断点续跑机制 | wait/续接机制或可恢复脚本 | 优先原生等待；再用断点续跑；用户本地执行是最后手段 |
| 删除或工作区外写入 | 当前 Claude 权限工具 | 当前 Codex 沙盒审批 | 解析精确路径并走当前运行时审批，不引用别的平台授权工具 |

如果某个平台更新了工具名，只修改本表和直接依赖本表的少量执行说明，不要在所有 task reference 中复制新工具名。

## 三、跨平台文件写入纪律

### 小型文本改动

- 优先使用运行时提供的结构化编辑工具。
- 保留用户已有改动；先读取目标上下文，再做最小补丁。
- 修改后检查 diff、文件尾部和 UTF-8 编码。

### 大型研究文件和构建脚本

- 不假定某一平台的 `Write`、`Edit` 或 shell 一定能安全处理大文件。
- 生成型文件优先由确定性脚本一次构建；反复修改时使用明确锚点，报告命中数和未命中项。
- 需要整文件替换时，先写到同一目录的临时文件，验证通过后再原子替换目标。
- 校验项至少包括：文件非空、末尾完整、无 U+FFFD、UTF-8 可读、预期锚点数量正确，以及适用的 `py_compile`、`node --check` 或解析测试。
- 不使用尾部盲追加修补未知截断点；先识别完整结构再恢复。

### Shell 与路径

- Windows PowerShell、Unix shell 和容器路径语法不同。先识别当前 shell，不要把 Bash heredoc、`rm/cp/mv/head` 或 Linux 挂载路径直接用于 PowerShell。
- 传递路径时使用当前系统的绝对路径和安全的字面量参数；不要拼接未经验证的删除目标。
- 能用 Python 跨平台脚本完成的确定性任务，可优先使用 Python；但文件内容修改仍遵守当前运行时的编辑规则。

## 四、长任务执行顺序

批量下载 filings/字幕、十几张图、AI 图片或大型 DOCX 构建可能超过单次工具调用时限。按以下顺序处理：

1. **使用当前运行时原生长任务能力**：设置合理超时；若返回可续接的任务 ID，则用 wait/continue 机制轮询，同时保持进度更新。
2. **拆分为可验证批次**：按公司、文件、图表或章节分批；每批完成后写 manifest/checkpoint。
3. **使用可恢复脚本**：脚本维护 `manifest.json`，跳过已完成项，失败自动重试 2-3 次并打印进度。
4. **用户本地执行作为最后手段**：仅当当前运行时确实无法持续运行、且任务需要用户环境或登录态时，才生成脚本请用户运行。明确所需依赖、输入、输出目录与安全注意事项。
5. **拾取与验证**：读取产出；图片逐张视觉检查，Excel/DOCX 做结构和渲染检查，失败项重跑而不是盲目装配。

不要写死“所有沙盒都有 45 秒上限”。超时行为属于运行时能力，应在实际会话中检测。

### 可恢复脚本要求

1. 断点续跑：维护 manifest，重跑跳过成功项。
2. 自动重试：2-3 次，带退避。
3. 进度可见：打印 `[完成数/总数]`、当前对象和输出路径。
4. 幂等：同一输入重复执行不会损坏已有成功结果。
5. 凭证安全：API key 从环境变量或安全输入获得，不写进脚本、日志、报告或版本库。
6. 输出校验：文件非空、格式可解析，并记录失败原因。

## 五、网页与浏览器能力 fallback

1. 优先使用当前运行时的搜索和页面打开能力获取公开页面。
2. 动态页面、登录态页面或 transcript 面板需要浏览器自动化时，使用当前已安装的浏览器能力；不要假定 `web-access`、CDP、Chrome 远程调试或某个站点脚本必然存在。
3. 浏览器能力不可用时，降级到公开页面、公司 IR、监管文件、RSS/API、视频简介或用户上传文件，并显式标记缺口。
4. 未取得完整正文/字幕时不得声称已全文阅读；视频观点必须注明是否为完整字幕、自动字幕、简介或二手转述。

---

## 六、删除、覆盖和凭证安全

- 删除或覆盖前解析精确绝对路径，确认目标位于用户授权范围内。
- 使用当前运行时的审批机制；不要调用另一个平台的删除授权工具，也不要通过 shell 绕过权限。
- 尽量采用可恢复操作和版本化输出。物质性删除后说明删除内容及是否可恢复。
- 用户在聊天中明文贴出 API key/token/password 时，立即提醒轮换；不要把凭证写入脚本、注释、日志或交付物。

---

## 七、各 Task 的适用点

- **Task 1**：批量 filing、transcript、网页与视频资料；按网页 fallback 和可恢复下载执行。
- **Task 2**：Excel 构建；按可用表格能力或 XLSX 库执行，构建后做公式、格式和联动验证。
- **Task 3**：修改既有 Excel；先保存版本化副本并验证估值链路。
- **Task 4**：批量出图；分批生成、逐张视觉 QA、汇总 contact sheet。
- **Task 5**：大型 DOCX 构建；使用确定性构建脚本、结构校验、渲染检查和双闸门。
